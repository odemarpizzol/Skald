# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Skald is a World of Warcraft Classic-family addon (the repo keeps `## Interface: 16001`; the test client is Anniversary, TOC 20506 only in the copy): an epic first-person auto-diary shown as an open leather book. Texts in en/ptBR/frFR. The user replies and works in Portuguese. This clone is the official workspace; the addon is copied into `Interface\AddOns\Skald` of the game folder (under Windows, `D:\Games\World of Warcraft\_anniversary_`; never copy `dev` into `_retail_`, that has its own `retail` branch) only to test it in the game. See `dev/HANDOFF.md` for the state of the work and the user's preferences, and `dev/ROTEIRO_TESTE_0.37.md` for the in-game test script.

## Commands

```
npm install --prefix dev/tools        # once
node dev/tools/checks.js              # everything: syntax, textures, lint, phrases en/pt/fr, simulated session, regressions, Reader, speed
node dev/tools/regressions.js         # only the regression scenarios (add one per bug found in the game, before fixing it)
node dev/tools/validate_phrases.js    # only the phrase pools
node dev/tools/lint.js [--update-baseline]   # scope-aware lint; --update-baseline accepts a new game API global
node dev/tools/serve_docs.js          # preview of the web Reader (docs/reader)
```

Run `checks.js` before saying anything is ready. It runs Lua 5.3 in fengari with `dev/tools/mock.lua` standing in for the WoW API: a green run means "no obvious error", **not** "works in the game". Always tell the user the simulation is not the game.

The tools resolve the addon as `<parent of repo>/Skald`, so the clone folder must be named `Skald`. `dev/tools/release.js` still assumes the old `Skald-publish` layout and has not been adapted to this clone.

The release workflow runs `checks.js` first (job `checks`, then `release`); it needs `dev/tools` committed.

Releases: bullets in `dev/NEXT_CHANGELOG.md` (English), version in `Skald.toc` and `CHANGELOG.md`, commit, then push a tag `vX.Y.Z-beta`; GitHub Actions (`.github/workflows/release.yml`, BigWigs packager, secret `CF_API_KEY`) uploads to CurseForge (project 1748824). `.pkgmeta` excludes `dev`, `docs`, `.github`, README and CHANGELOG from the package. Publish only when the user says "publica"; the user picks the version number.

## Architecture

Load order (`Skald.toc`): `Locales.lua`, `Curated.lua`, `XPTiers.lua`, `Skald.lua`, `Atlas.lua`, `Goals.lua`, `Saga.lua`, `ZoneCard.lua`, `Backup.lua`, `Search.lua`, `Bard.lua`; shared through the addon namespace `ns`. SavedVariables: `SkaldDB`, `SkaldAtlasDB` (account), `SkaldCharDB` (per character).

- Everything the diary knows about a character besides pages (pets, companions, flights, goals, standings...) is listed in `K.DIARY_STATE`: it is cleared with the diary and archived/restored with it. A new per-character key in `SkaldCharDB` must be added there.
- A new goal in `Goals.lua` must carry `since = <the next GOALS_VERSION>` and `GOALS_VERSION` must go up with it; without that every existing diary writes a page and a notice for each goal it finds already done on its next login. Points come from the seal (`tier`) and are never stored.
- **The diary stores IDs, numbers and a phrase index (`idx`), never text.** Page text is built live (`PoolFor` / `RenderEntry` / `Extras` in `Skald.lua`) from phrase pools in `Locales.lua`, so a change of language or of voice rewrites old pages. Anything that rewrites pages in place must bump `ns.layoutRev` (the page layout is cached in `Layout()` inside `CreateWindow`).
- `Skald.lua` (~6400 lines) holds events (`EVENT_HANDLERS` table, dispatched by `HandleEvent`), milestones (`Mile`), the book window (`CreateWindow`, ~1200 lines), settings tabs (`f:AddTab`, order by `TAB_RANK`; "Settings" is one tab (`BuildSettings`, `K.SETTINGS_PAGES`) holding three spreads, Style, Notices and Options, that the corners of the book turn (a `pager`, folio vii, ix, xi); `/skald qa` walks each under it only while one is open; the cover keeps its tab), export (`BuildExport`, `PlainText`, the Reader format) and the slash commands. Constants and helpers live in the tables `K`, `Mile` and `ns`, because the WoW Lua 5.1 chunk is limited to 200 locals (lint fails past that).
- `Atlas.lua`: world-map pins, built in since 0.31 (standalone SkaldAtlas is only a stub). `Goals.lua`: the clickable Goals tab, using the `AddTab` pattern; new tabs should copy it. `Curated.lua`: hand-written quest stories. `XPTiers.lua`: level/XP tiers.
- `docs/reader`: the web Reader (GitHub Pages, main branch `/docs`), plain HTML/JS with no dependencies. The game exports text with `/skald reader` (header, one line per page, fields separated by a caret `^`, parts with a checksum); the user pastes it in the page, nothing is sent anywhere. `dev/tools/reader_test.js` tests the parser against a real simulated export.
- `ZoneCard.lua`: the card on the right page of the Index when the contents fit on the left (`ns.ZoneCard`): the map of the zone drawn from the game's own tiles (`C_Map.GetMapArtLayers/GetMapArtLayerTextures`, sepia by desaturate + vertex colour), regions found (`C_MapExplorationInfo`, no total exists), quests of the zone done/total (QuestDB through LibStub, filtered by race/class bitmasks, hidden and repeatable out; without QuestDB the diary's own count) and creatures slain there (`Mile.TrackKills` adds the difference of the game's kill statistic to the zone underfoot; `zoneKills`/`killBase` are in `K.DIARY_STATE`). Treasures have no source and are left out.
- `Backup.lua`: `/skald backup` (whole diary as text, in parts of 16000 characters) and `/skald restore` (parts pasted in any order, one window). It is a typed serializer and a hand-written parser, never `load`: plain ASCII (a bar `|`, spaces and every byte outside the printable range are written `\XX`), key types kept (`stats.dayset` has digit-string keys, `stats.tiers` number keys), `false` kept. It saves every key of `SkaldCharDB` except `previous`, `probeLog` and `restoreUndo` (so a new per-character key travels without being listed), checks version, per-part and whole checksums, types and structure on a candidate before touching anything, and restores only on the character it came from (same guid). The diary replaced is kept whole as ONE undo copy in `db.restoreUndo` (not in `db.previous`, which holds three and would let one go); `/skald restore undo` swaps it back. After a swap `ns.ReadAfresh` (flags, day in progress, professions, guild read again, as for an archive) and `ns.RefreshDiary` run; a failure after the swap puts the old diary back. The window uses plain templates and has not been seen in the game; the size of a part is `Backup.PART_LIMIT`.
- `Search.lua`: the Search tab (`TAB_RANK` 2.5, right after the Index and before the Journeys tab, as both help to find a page). `ns.Search.Run(entries, query, opts)` is a plain function (no window) that matches every word of the query against the text each page is told with now (`SkaldAPI.Render` + place + giver + companions + favourite note), capitals and accents folded (`Search.Fold`, Latin two-byte letters), newest first, at most `Search.MAX` listed with the full count returned; `opts` = `group` (a key of `Search.GROUPS`), `favs`, `days`, `now`. The told text is cached per page and told again when `ns.layoutRev` or the language changes, so anything that rewrites pages must bump `ns.layoutRev` (it does already). The box looks a quarter of a second after the last key; a click on a row calls `SkaldAPI.OpenEntry` and says so when the book has no page for it (every page is in the book; only a second summary of the same date, which the book keeps one of, is not). `LayoutTabs` closes the step between tabs when there are many, so the column stays above the foot of the cover. The tab has not been seen in the game.
- `Bard.lua`: the Bard tab (`TAB_RANK` 3.7), a jukebox of 33 pieces of the game's own music, six to a page of the list (the corners of the book turn it), with a "Shuffle" check (`SkaldDB.bardShuffle`: next/before choose by chance, before goes back through `Bard.history`; the game says no end of song, so `Bard.Tick` (every 0.15 s, from the driver frame) moves on by itself when the length of the file, `len` in `Bard.TRACKS`, has run: the lengths were read from the files themselves, the game plays a piece in a loop and says nothing when it comes round) (`Bard.TRACKS`, by file number: `PlayMusic(id)` / `StopMusic()`, names in `L.BARD_TRACKS`). The game cannot pause, seek, say the length or say when a piece ends (it loops until stopped), so there are Play/Stop, previous/next going round, a clock of the time played counted here, and the volume bar sets the CVar `Sound_MusicVolume` (global to the game, said on the page); with `Sound_EnableMusic`/`Sound_EnableAllSound` at 0 nothing plays and the page says so. Music keeps playing when the book closes. The pieces and the tab have not been heard or seen in the game. While a piece plays a frame of its own (`driver`) shows `bard_notes_1..4` by the hearth, `bard_eq_1..3` under the list and `bard_note_on` on the tab. Art: `Textures/skald2/bard_*.tga` and the tab leather `tab_idle`/`tab_active`.
- The looks of the tabs (`K.TAB_STYLES`, chosen in the Style tab with `SkaldDB.tabStyle`: leather, ribbon, brass, parchment, wood): every picture is `Textures/skald2/tab_*.tga`, 256x128 shown at half size with the leather 110x31 at the same place, so a look is a picture, a place for the letters and an ink; the shut ribbons have a colour each (`K.RIBBON_COLORS`), the open one is always golden. A new look = its two pictures and one line in `K.TAB_STYLES` (+ its name in `L.TAB_LOOKS`, and in `K.TAB_STYLE_ORDER`); a regression checks that every picture named exists. With the book shut and a song playing, the Bard shows a notice on the screen (`panel.mini` in `Bard.lua`, place kept in `SkaldDB.bardPos`; its look, `SkaldDB.bardHud`: bar, scroll, wood or medal (the plate drawn by the code was dropped; an old saved "plate" falls back to the bar), is chosen on the Bard tab with a preview of a few seconds; each look is `Textures/skald2/hud_<look>.tga` + `_icon` + `_stop`, 512-wide canvases shown at half size, the places of the socket, the button and the name in `HUDS` in `Bard.lua`).
- `Saga.lua`: `ns.BuildSaga()` tells the diary as chapters in the first person (a tab, pages by the size of the letter). Its phrases live in `Saga.lua` (`ns.SagaTexts`), are checked by `validate_phrases.js`, and each is picked by a hash of the diary's first date, so the same diary gives the same Saga. The Saga also travels in the Reader export as `V` lines (parsed in `docs/reader/reader.js`, which skips line types it does not know). Reading aloud (`ns.SpeakTexts`, `/skald read`) uses `C_VoiceChat.SpeakText(voice, text, rate, volume, false)` as DialogueUI does in this client; the user found the voice poor, so it is switched off (`ns.SpeechOn = false` in `Skald.lua`; the code, the Listen button and `/skald read` stay and come back with the flag). The larger plan (Saga, shared chronicle, TTS, memories of time) is in the user's plan file `refactored-discovering-aurora.md`.

## Art

All art is made by the user, a human, directly in Claude Design; Claude Code does not draw it. When Claude sees an opportunity for an icon or picture (a new page kind, a family, a seal, a tab, a Reader header), it should say so and write a ready-to-paste prompt for Claude Design. That prompt must follow strictly the style of the art already in the addon (look at `Textures/` and `docs/reader/img` first and describe that style in the prompt: same palette, line, lighting, framing and level of detail), and ask for the size and margin needed (power-of-two canvas, about 8% free space at the edges so nothing touches the border). The user sends the PNGs back (zip in `Interface\` or Downloads); Claude converts them to TGA (32-bit, power of two) with sharp, wires them in code and runs `checks.js`. Never ship a placeholder or an invented picture in place of the user's art.

## Rules that are easy to break

- Lua is the 5.1 of the WoW client: no `\u` escapes, no Lua 5.3 features. Write Lua/JS containing backslashes with the Write/Edit tools; the shell (heredoc, `node -e`) swallows them.
- Every new string or phrase goes in all three locale blocks (en/pt/fr) of `Locales.lua`. French is written by Claude without native review; `Locales.lua` is its source of truth (do not regenerate it), and French punctuation uses NBSP (`\194\160`) before `: ; ? !` and inside «». Pools should have at least 8 variants (`validate_phrases.js` lists the shorter ones as debt, and it fails below 5; today none is below 8); `AddEntry` avoids repeating a phrase within the last 5 of the same kind (a regression covers it). Gendered words use the `{g:he|she}` tag (`ns.Gendered`).
- In the Reader text a bar `|` starts an escape code in the game's text boxes, hence the caret as field separator.
- New textures: TGA 32-bit, power-of-two size, in `Textures/` (all names used in code are checked by `checks.js`). They only show in the game after a full restart, not `/reload`.
- Pages are written when the event fires, in combat too (`AddEntry` has no combat check; only memories wait). Do not claim the contrary in docs; payloads the client withholds are skipped with `Safe()`.
- Several events are still unverified in the real client (see README "Limits").
- User preferences: no TRP3 integration; Goals stay a clickable list; phrase variety is a permanent wish; no tiny versions; art is made by the user in Claude Design (prompt the user, they send PNGs, convert to TGA with sharp).
